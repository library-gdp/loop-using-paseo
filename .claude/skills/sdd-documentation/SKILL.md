# 8. Documentation

검증이 끝난 형상을 `docs/` 아래 중앙 문서에 반영하라. Verification Gate를 통과한 뒤에 수행하므로, 문서에 들어가는 내용은 이미 인수 테스트로 검증된 사실이다. 이 단계에서는 코드를 고치지 않는다.

공통 규칙은 `sdd-workflow` 스킬을 따른다.

## 입력

- `$TASK_DIR/01.plan/PLAN.md`의 "중앙 문서 최신화" 절
- `$TASK_DIR/00.explore/EXPLORE.md`의 "관련 중앙 문서" 절
- `$TASK_DIR/02.architecture/` 의 세 문서 (변경 이력 포함)
- `$TASK_DIR/06.verification_gate/EVALUATION.md`의 마지막 iteration 섹션 — 최종 판정과 미충족 AC
- 기준 커밋(`EXPLORE.md`에 기록) 이후의 코드 변경
- `docs/` 아래 기존 중앙 문서

## 핵심 규칙

- **이미 있는 문서만 최신화한다. 없는 문서를 새로 만들지 마라.** `PLAN.md`에 새 문서가 필요하다고 적혀 있어도 만들지 않는다. `docs/` 디렉토리 자체가 없으면 만들지 말고 "최신화할 문서 없음"으로 기록하라.
- 새 중앙 문서가 필요하다고 판단한 것은 `DOCUMENTATION.md`의 "새 문서 제안"에 적어라. Report가 이를 후속 제안으로 넘긴다.
- **검증된 것만 반영한다.** 최종 판정이 "최대 iteration 초과 통과"여서 미충족 AC가 있으면, 그 부분은 문서에 반영하지 마라. 이미 있던 서술이 사실과 달라졌다면 현재 사실에 맞게 고치고, 무엇을 왜 반영하지 않았는지 기록하라.
- 중앙 문서에는 **프로젝트의 현재 상태**를 서술하라. "이번 작업에서 ~를 바꿨다" 같은 작업 이력 서술은 `runs/` 기록이 담당하므로 중앙 문서에 쓰지 마라.
- `runs/` 아래 기록은 최신화 대상이 아니다. 이번 작업의 `07.documentation/` 외에는 아무 기록도 고치지 마라.
- Notion을 갱신하지 마라. 중앙 문서는 `docs/`에서만 관리한다.

## 절차

1. `$TASK_DIR/07.documentation/`을 만들고 타임라인을 기록하라.
   ```bash
   node .claude/skills/sdd-workflow/scripts/timeline.mjs mark "$TASK_DIR" documentation - start
   ```
2. `PLAN.md`의 "중앙 문서 최신화" 표를 읽어 대상 문서 목록을 만들어라.
3. 대상 문서가 실제로 있는지 확인하라.
   ```bash
   ls docs/ 2>/dev/null || echo "docs/ 없음"
   ```
   - 계획에 있지만 파일이 없는 문서는 **만들지 말고** 제외하라. 제외 사실과 이유를 기록하라.
   - `docs/`가 없으면 4~6번을 건너뛰고 "최신화할 문서 없음"으로 `DOCUMENTATION.md`를 작성하라.
4. 기준 커밋 이후의 코드 변경(`git diff <base> -- . ':!runs'`)과 Architecture 문서를 읽어, 문서에 반영할 **현재 사실**을 확정하라. 계획에 적힌 내용과 실제 구현이 다르면 실제 구현을 기준으로 삼아라.
5. 문서마다 해당 절을 고쳐라.
   - 계획에 적힌 범위만 고쳐라. 눈에 띄는 다른 서술을 고치고 싶으면 "범위 밖 문서 과제"에 적어 두고 손대지 마라.
   - 기존 문서의 구성, 제목 수준, 문체, 표 형식에 맞춰라. 문서 전체를 다시 쓰지 마라.
   - 고친 뒤 해당 절을 다시 읽어, 서술이 코드와 일치하는지 코드 위치를 근거로 확인하라.
6. 계획에 없었지만 이번 작업으로 사실이 달라진 기존 문서 서술을 발견하면, 그 문서가 `docs/`에 이미 있는 경우에만 함께 고치고 `DOCUMENTATION.md`에 "계획 외 최신화"로 적어라.
7. `$TASK_DIR/07.documentation/DOCUMENTATION.md`를 아래 템플릿으로 작성하라.
8. `git status --short -- docs`로 변경된 문서를 확인하고, 새로 생긴 파일(`??`)이 없는지 점검하라. 있으면 이 단계의 규칙 위반이므로 되돌려라.
9. 타임라인을 기록하라.
   ```bash
   node .claude/skills/sdd-workflow/scripts/timeline.mjs mark "$TASK_DIR" documentation - end
   ```
10. 사용자에게 최신화한 문서 목록과 반영한 내용, 제외한 문서와 이유를 짧게 보고하라.

## DOCUMENTATION.md 템플릿

```markdown
# DOCUMENTATION — <작업 제목>

- 수행: <YYYY-MM-DD HH:MM>
- 최종 판정: <통과 / 최대 iteration 초과 통과>
- 기준 코드: `<base>`..작업 트리

## 1. 최신화한 중앙 문서
| 문서 | 고친 절 | 반영한 사실 | 근거 (코드 위치 / AC) |
|---|---|---|---|
| `docs/...` | <절 제목> | ... | `app/src/...:42`, AC-01 |

최신화한 문서가 없으면: 없음 — <이유>

## 2. 계획 외 최신화
| 문서 | 고친 절 | 이유 |
|---|---|---|

## 3. 최신화하지 않은 계획 항목
| 문서 | 이유 |
|---|---|
| `docs/...` | 문서가 없어 제외 (새 문서는 만들지 않는다) |
| `docs/...` | 미충족 AC에 해당해 반영 보류 |

## 4. 새 문서 제안
- <새로 있으면 좋겠다고 판단한 중앙 문서와 이유. 이번 작업에서 만들지 않았다.>

## 5. 범위 밖 문서 과제
- <이번 작업 범위를 벗어나 고치지 않은 중앙 문서 불일치>
```

## 완료 조건

- `PLAN.md`에 계획된 대상 중 `docs/`에 실제로 있는 문서가 모두 최신화되었다.
- `docs/` 아래에 새로 만든 파일이 없다.
- 최신화한 서술마다 코드 위치나 AC를 근거로 들 수 있다.
- 최신화하지 않은 계획 항목에 이유가 적혀 있다.
- `docs/` 밖의 파일과 `runs/`의 다른 기록이 변경되지 않았다.

# 1. Explore / Analysis

올바른 계획을 세울 수 있도록 요청 내용과 요구사항을 정확히 이해하고, 현재 프로젝트 형상을 파악하라. 이 단계에서는 코드를 수정하지 않는다.

공통 규칙(작업 디렉토리 이름, 타임라인, 불변 규칙)은 `sdd-workflow` 스킬을 따른다.

## 입력

- 사용자의 작업 요청 원문
- `$TASK_DIR` (없으면 `sdd-workflow`의 "0. 준비"를 먼저 수행하라)

## 절차

1. `$TASK_DIR/explore/`를 만들고 타임라인을 기록하라.
   ```bash
   node .claude/skills/sdd-workflow/scripts/timeline.mjs mark "$TASK_DIR" explore - start
   ```
2. **요청 분석**: 요청 원문을 요구사항 단위로 쪼개라. 각 요구사항을 기능 요구사항과 비기능 요구사항(성능, 배포, 호환성 등)으로 분류하라.
3. **프로젝트 규칙 확인**: `CLAUDE.md`, `README.md` 등 프로젝트 지침 문서에서 이번 작업에 적용되는 제약만 추려라.
4. **선별 탐색**: 요구사항과 관련된 파일만 골라 읽어라.
   - 먼저 디렉토리 구조와 진입점(예: `package.json`, `main.ts`, 설정 파일)으로 범위를 좁힌 뒤, 요구사항에 닿는 모듈만 깊이 읽어라.
   - 관련 없는 파일을 전수 조사하지 마라. 넓은 검색이 필요하면 Explore 서브에이전트에게 맡기고 결론만 받아라.
   - 읽은 파일마다 왜 읽었는지 한 줄로 기록해 두어라.
5. **현재 상태 정리**: 관련 모듈의 역할, 데이터 구조, 설정·환경변수, 빌드·실행 방법, 기존 테스트 수단, 이번 작업이 영향을 줄 지점을 정리하라.
6. **기준 커밋 기록**: `git rev-parse HEAD`, 현재 작업 브랜치, 작업 브랜치를 분기한 원점 브랜치를 기록하라. Review 단계는 이 커밋을 기준으로 diff를 보고, Report 단계는 분기 원점 브랜치를 PR base로 쓴다. 기존 브랜치에서 작업을 이어서 해 분기 원점이 없으면 "없음"으로 적어라.
7. **모호점 처리**: 요구사항이 여러 방식으로 해석되고 그 선택이 계획을 바꾸면 사용자에게 질문하라. 합리적인 기본값이 있으면 가정으로 기록하고 넘어가라.
8. `$TASK_DIR/explore/EXPLORE.md`를 아래 템플릿으로 작성하라.
9. 타임라인을 기록하라.
   ```bash
   node .claude/skills/sdd-workflow/scripts/timeline.mjs mark "$TASK_DIR" explore - end
   ```
10. 사용자에게 산출물 경로와 핵심 내용(요구사항 수, 영향 범위, 가정·미확인 사항)을 짧게 보고하라.

## EXPLORE.md 템플릿

```markdown
# EXPLORE — <작업 제목>

- 작성: <YYYY-MM-DD HH:MM>
- 작업 브랜치: `<branch>` (분기 원점: `<parent branch 또는 없음>`)
- 기준 커밋: `<sha>`

## 1. 작업 요청
<요청 원문을 그대로 인용하거나 핵심을 요약>

## 2. 요구사항
| ID | 구분 | 요구사항 | 출처 |
|---|---|---|---|
| R-01 | 기능 | ... | 요청 원문 / CLAUDE.md / ... |
| R-02 | 비기능 | ... | ... |

## 3. 적용되는 프로젝트 제약
- <CLAUDE.md 등에서 추린 제약과 그 영향>

## 4. 현재 프로젝트 형상
### 4.1 구조 요약
<관련 디렉토리·모듈과 역할>

### 4.2 관련 코드·설정
<모듈별 현재 동작, 데이터 구조, 환경변수, 실행·빌드 방법>

### 4.3 영향 범위
<이번 작업으로 바뀌거나 영향을 받는 파일·모듈>

## 5. 탐색한 파일
| 파일 | 읽은 이유 |
|---|---|

## 6. 가정과 미확인 사항
- 가정: <합리적 기본값으로 정한 것과 근거>
- 미확인: <확인하지 못한 것과 계획에 주는 위험>
```

## 완료 조건

- 모든 요구사항에 ID가 붙어 있고, Plan 단계가 이 문서만 보고 계획을 세울 수 있다.
- 기준 브랜치와 커밋이 기록되어 있다.
- 계획에 영향을 주는 모호점이 질문으로 해소되었거나 가정으로 기록되어 있다.
